## 1. 核心摘要

为销售业务新建"销售报价管理"单据：表头记录客户、报价日期、销售员、币别、有效期与报价状态；明细按产品逐行记录数量、单价、折扣率，报价金额按"数量 × 单价 × 折扣率"自动计算。单据遵循平台"保存 → 提交 → 审核"标准生命周期，开发完成后发布菜单入口。

## 3. 用户故事

### 3.1 US-001 · 销售员创建并提交销售报价单

**基本信息**

| 字段 | 值 |
| --- | --- |
| 故事ID | US-001 |
| 故事名称 | 创建销售报价单 |
| 用户角色 | 销售员 |
| 优先级 | P0 |
| 场景类型 | Create |

**故事描述**：作为销售员，我想要按客户和产品录入报价明细并自动计算报价金额，以便于向客户出具正式报价并跟踪报价审核状态。

| 实体编码 | bd_customer（客户） | 关联基础资料（主对象引用的主数据） | Existing |
| 实体编码 | bd_material（物料/产品） | 关联基础资料（主对象引用的主数据） | Existing |

**操作按钮**

| 按钮 | 点击后行为 |
| --- | --- |
| 保存 | 保存单据（未提交状态） |
| 提交 | 提交单据，状态推进为"已提交" |
| 审核 | 审核已提交单据，状态推进为"已审核" |

**业务规则**

校验规则：

| 规则编码 | 应用字段/场景 | 规则 |
| --- | --- | --- |
| VAL-001 | 客户、报价日期、销售员、币别、报价状态 | 必填，缺失时拦截保存 |
| VAL-002 | 有效期 / 报价日期 | 有效期不得早于报价日期 |
| VAL-003 | 折扣率 | 取值 0~1，越界拦截 |
| VAL-004 | 数量、单价 | 不得为负 |
| VAL-005 | 明细分录 | 至少一行产品明细 |

计算规则：

| 规则编码 | 触发字段 | 计算公式 |
| --- | --- | --- |
| CAL-001 | 数量、单价、折扣率 | 报价金额 = 数量 × 单价 × 折扣率（编辑即刷新） |

联动规则：

| 规则编码 | 触发字段 | 联动行为 |
| --- | --- | --- |
| LNK-001 | 产品 | 选择产品后带出该产品计量单位（E-003） |

其他规则：

| 规则编号 | 规则描述 |
| --- | --- |
| BIZ-001 | 手工单据编码；生命周期为 保存→提交→审核；不承诺自动编号（E-006） |
| BIZ-002 | 已审核单据不可直接修改，需反审核后修改（平台标准行为） |

**验收标准**

- [ ] **AC-US001-01**：给定新建空单，录入表头六个字段并保存，系统保存成功；重新打开单据，各字段值与录入一致。
- [ ] **AC-US001-02**：录入至少一行明细（产品、数量、单价、折扣率）并保存，重新打开后明细各字段值与录入一致。
- [ ] **AC-US001-03**：修改明细行的数量、单价或折扣率，该行报价金额按"数量 × 单价 × 折扣率"实时刷新。
- [ ] **AC-US001-04**：币别字段可打开下拉，并选中平台币别基础资料中的值。
- [ ] **AC-US001-05**：有效期早于报价日期时执行保存，系统拦截并提示有效期不得早于报价日期。
- [ ] **AC-US001-06**：折扣率输入超出 0~1 的值，系统拦截并提示取值范围。
- [ ] **AC-US001-07**：明细无任何产品行时执行保存，系统拦截并提示至少录入一行明细。
- [ ] **AC-US001-08**：单据依次执行保存、提交、审核，报价状态按 未提交→已提交→已审核 推进；已审核单据不可直接修改。

## 4. 业务需求

### 4.1 功能性需求

| ID | 需求描述 | 优先级 | 对应故事 |
| --- | --- | --- | --- |
| FR-001 | 用户必须能够新建销售报价单，录入表头六字段与明细五字段 | P0 | US-001 |
| FR-002 | 系统必须按"数量 × 单价 × 折扣率"自动计算明细报价金额 | P0 | US-001 |
| FR-003 | 系统必须按必填、有效期、折扣率范围、明细非空规则校验并拦截 | P1 | US-001 |
| FR-004 | 用户必须能够执行保存、提交、审核，报价状态随生命周期推进 | P0 | US-001 |
| FR-005 | 实施人员必须能够在开发完成后发布"销售报价管理"菜单 | P0 | US-002 |

### 4.2 非功能性需求

- 性能：单据保存与列表查询遵循平台通用约束（单次查询 ≤1 万条、保存 ≤2000 行）。
- 安全：遵循租户隔离与基于角色的访问控制；菜单与单据操作受权限项控制。
- 可用性：客户、产品、人员、币别等选择字段使用平台标准引用控件，支持模糊检索。

## 6. 假设条件

- A-001：目标应用为已有应用 bnuy_app_demo01（Demo应用01），本单据创建于该应用下。
- A-002：表头主要字段（客户、报价日期、销售员、币别、报价状态）必填；有效期建议必填，可按业务调整。
- A-003：默认值（报价日期=当天、销售员=当前用户、折扣率=1、报价状态=未提交）为专家建议，可按业务调整。
- A-004：明细"单位"字段为专家建议补充（平台数量字段需配套计量单位），业务不需要时可裁剪。
- A-005："产品"按平台物料主数据（bd_material）映射；若租户使用独立"产品"基础资料，以开发阶段实际引用为准。
- A-006：报价状态与平台自动单据状态的联动方式（同步推进或独立维护）由开发阶段按平台标准能力实现。
